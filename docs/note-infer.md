**命名认知**：`infer` 指模型运行与生成计算流，`reasoning` 指上层思维链 / Agent 规划；工程目录统一用 `infer`。

**目录粒度**：`infer/` 下每引擎独立子文件夹，而非平铺 `.yml`。


| 维度                          | 平铺 .yml              | 独立子文件夹         |
| ----------------------------- | ---------------------- | -------------------- |
| 附属文件（serve.sh / config） | 散落根目录             | 就近内聚             |
| compose 项目名                | 退化为父目录名，易冲突 | 各自目录名，天然隔离 |
| .env                          | 共用一份               | 每引擎独立           |

**三大冲突避坑**：Docker 项目名冲突用 `test-` 前缀或 `COMPOSE_PROJECT_NAME` 隔离；端口按引擎分段（如 28000/28001/28002）；显存互斥测试或各自限制 `gpu-memory-utilization`。

**调度入口**：Makefile 借 `.PHONY` 当任务管理器是云原生惯例，但本职是编译、认知阻抗大；`manage.sh` + `case in` 心智无负担，选脚本。
